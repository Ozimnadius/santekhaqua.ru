- **Сервер:** прод — https://santekhaqua.ru, PHP 8.2.28; шаги идут на прод и проверяются там.
- **Работа на сервере:** SSH — `ssh santekhaqua`, папка сайта `/var/www/user1867/data/www/santekhaqua.ru`, PHP CLI `/opt/php82/bin/php` (команда `php` на сервере — 5.4, не она); `/kit:server` работает по SSH, файл `kit-exec.php` — запасной путь.
- **Выкладка:** Claude по SSH: правки шага заливает `/kit:step-done` после просмотра (скрипт `ssh-deploy.js` — всё, что изменилось с последней заливки, и удаления), затем проверка на сервере и коммит; автозаливка PhpStorm выключена — иначе файлы уедут дважды.
  - Не выкладываются: `.idea`, `.git`, `.claude`, `.gitignore`.
  - Из `.claude/` на сервер уезжают только документы: их заливает `/kit:step-done` перед коммитом шага (`ssh-deploy.js --docs`, «Документы на сервере: да») — `.claude/docs` (без снимков `visual`), `CLAUDE.md` и `.htaccess` (первым); остальное в ней (скрипты, скиллы, служебные файлы) не уезжает, ручная выкладка `.claude` не включает («Не выкладывать»); снаружи папку закрывает `.htaccess` (`Require all denied`); проверка снаружи — `check-closed` (2026-10-21: документы `.claude` — 403, открытых нет).
  - Удалённый в git файл `ssh-deploy.js` удаляет и на сервере; прочее (старые копии) — раздел «Удалить с сервера» плана выкладки.
- **Синтаксис:** `C:\OSPanel\modules\PHP-8.2\php.exe -l <файл>` — хук плагина делает это после каждой правки PHP.

## Безопасность

- Сайт живой: каталог, корзина и оформление заказа (модуль `sale`), веб-формы (модуль `form`), почта домена (`info@santekhaqua.ru` на этом же хостинге). Правки шапки и подвала задевают все страницы — после каждого шага проверять главную, каталог, карточку товара и контакты на десктопе и мобильной ширине; изменения на сервере — только после просмотра пользователем.
- Секреты — только в /bitrix/.settings_extra.php, в git не класть.
- Снимки публичной части (`/kit:visual`) — в `.claude/docs/visual/`, только локально: в git и на сервер не попадают (снимки из-под админа; nginx отдаёт картинки мимо `.htaccess`).

## Как работаем

- **Код пишет Claude.** Один шаг за раз: код → `php -l` → запись в проект → `/kit:step-done`: просмотр, заливка по SSH, проверка результата на сервере одним пакетным вызовом браузера (`browser_batch`: открыть, снимок на десктопе, мобильная ширина, снимок; снимки уменьшенные), коммит → следующий шаг.
- **Выбор** за пользователем, вопросы — только через AskUserQuestion.
- **Документы** — в `.claude/docs/`: журнал и план выкладки в корне; планы, спеки, чек-листы, материалы задач — в `work/`; готовое и устаревшее — в `archive/`; реестр — раздел «Документы» журнала (новый документ — строкой DOCS в `/kit:step-done`, в архив — при закрытии этапа).
- **Крупная задача** — `superpowers:brainstorming` и `writing-plans` по правилам kit: спека и план — в `.claude/docs/work/` (`spec-<тема>.md` по шаблону kit, `plan-<тема>.md` с разделом «Чек-лист» в начале: строка на задачу `- [ ] N.M — …`, шаги внутри задач — без чекбоксов; закрытые шаги отмечает `/kit:step-done`), не в `docs/superpowers/`; сам superpowers не коммитит — задача плана = шаг kit, коммит через `/kit:step-done`; выбранный подход и отвергнутые — в «Решения» (строки про ветки нет — автозаливки нет).
- **После проверки шага** — `/kit:step-done`: скрипт `kit-journal.js` обновляет журнал и план выкладки, `kit-commit.js` делает один коммит `ID: …`.
- **Git** пользователь сам не трогает, команды git ему не выдаём.
- **Форматирование:** файлы целиком не переформатировать. Переводы строк — LF.

## Код

- Шаблон Аспро правим прямо в `bitrix/templates/aspro_max` (копии в `local/templates` нет). Телефоны, адрес, почта и соцсети по возможности — через настройки Аспро в админке и включаемые области (`include/`), а не правкой кода. Модули Аспро (`bitrix/modules/aspro.*`) и ядро не трогаем. Устаревшие `.min.css`/`.min.js` Аспро не трогать и не создавать.
- Рабочие папки в `bitrix/` — `bitrix/templates/aspro_max`: правят прямо там, поэтому они в git (исключения в `.gitignore` и «Не коммитить») и уезжают на сервер, как остальные файлы. Обновление ядра или решения (Аспро) меняет их на сервере — после него скачать эти папки с сервера заново и закоммитить (при «Claude по SSH» — шагом без заливки, точка отсчёта: `/kit:step-done`, `ssh-deploy.js --md5`), иначе правка такого файла зальёт поверх новой версии старую.
- Код на Битриксе — по скиллам в `.claude/skills/`: начинай с `bitrix-framework` (каноны D7, `/local/`, безопасность, версии ядра), практики — `bitrix-best-practice-core` и `bitrix-best-practice-sql`; для задачи открой подходящий скилл и только нужные `rules/*.md`. Скиллы не в git: нет `.claude/skills/bitrix-framework/` (например, после `git clone` на другом компьютере) — поставь их через `/kit:project-init`.
